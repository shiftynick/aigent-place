## Architecture decisions in force

- ADR-0002: shape grammar + collider + swept movement. Locked decision.
- ADR-0003: movement leases. Locked decision.
- ADR-0004: terminal revision for forced sleep. Locked decision.
- ADR-0005: durable-before-apply (generation install only after commit).
- ADR-0008: wire types come from `protocol/v1/aigent.proto` via `prost`.

No new ADR is required for task-054: the schema additions are reversible
(the new messages are additive, no existing field numbers or types
changed) and the implementation is confined to the new types in
crates/world-server/src/wire/snapshot.rs. Wire compatibility is preserved
because `FullSnapshot.payload` and `SnapshotDelta.payload` are still
`bytes`; the bytes just now carry `WorldSnapshotBodyProto` /
`WorldSnapshotDeltaProto` instead of the `AIGB` placeholder.

## Task-log decisions (in addition to the rubric above)

- The legacy `StubSnapshotPayload` / `AIGB` path is retained for the
  workload harness and the protocol conformance oracles, which drive
  interest from their own catalog and do not put a frame on the wire.
- `last_real_frame: Option<LastRealFrame>` and the
  `install_real_full` / `deliver_real_delta` methods are added to
  SnapshotChannel alongside the legacy `last_payload` /
  `install_full` / `deliver_delta` methods (no shared base type).
- AOI candidates for the real path read from the entity table; the
  legacy `aoi_candidates` (leases) is kept for the stub path.
- AOI diff in the real path compares revision and mm position, not just
  entity_id presence.
- The fanout's `enqueue_state` byte measure for the real path is the
  encoded frame the caller is about to write, except when
  `encoded_bytes` is set (test/pressure fixtures).
- The viewer uses a hand-rolled protobuf decoder
  (apps/viewer/src/wire/real-snapshot.js) for now. Auto-generated
  bufbuild bindings are present in the package, but a hand-rolled
  decoder was chosen for the small surface and to make the
  proto3 default-omission and packed-uint64 handling explicit.
- The shared fixture is regenerated by a Rust test
  (`write_conformance_fixtures`) and consumed by a node test
  (`apps/viewer/test/real-snapshot.test.mjs`). The fixture is
  hex-encoded, lowercase, single line, in
  `protocol/v1/conformance/binary/world-snapshot-{body,delta}.hex`.
- Three integration test files (live_aoi_behavior, listen_journal_behavior,
  outbound_pressure_accounting) were migrated to decode the new wire
  format. live_aoi_behavior now constructs entity tables with
  placeholder poses; outbound_pressure_accounting adds a
  `crowd_generation_with_offset` helper so each tick produces a
  non-empty diff.
